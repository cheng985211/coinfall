# 命途回廊 · COINFALL

> 在时间之外，有一座不存在的赌场。八个世界的故事被抵押在这里，每一次抛币，都是一段命运被重新裁定。

**纯 HTML / CSS / JavaScript 的浏览器抛币卡牌对战游戏（v2.0）。** 无需构建、无需框架、无需后端即可单机开玩；同一套代码支持 1v1 到 4v4、AI 同注者、**零配置公网 WebRTC 联机**（PeerJS 点对点，房间号即暗号）与可选的 Supabase 高级自定义。

## 立即开始

### 方式 A：双击开玩（最快）

直接双击 `index.html`。单机模式、AI 对战、卡牌图鉴、剧情挑战都可运行。

> 部分浏览器会限制 `file://` 下的语音合成 / 剪贴板功能。想要完整体验，建议用方式 B。

### 方式 B：本地服务器（推荐）

Windows 双击 `start.bat`；macOS / Linux 运行：

```bash
./start.sh
# 或
node server.mjs
```

然后打开：

- 本机：<http://127.0.0.1:8787/>
- 同一 Wi-Fi 下的手机 / 另一台电脑：`http://你的局域网IP:8787/`

启动脚本会直接打印可用的局域网地址。若手机打不开，检查 Windows 防火墙是否允许 Node.js 的专用网络入站。

### 方式 C：在线玩

GitHub Pages 永久地址：**<https://cheng985211.github.io/coinfall/>**

首次部署步骤见 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。

## 规则 60 秒

1. 双方各有 **5 点生命**（快速模式 3 点，一币定生死 1 点），各带 1 名角色与一副技能卡。
2. 开局抽 **3 张**手牌；之后每个自己的回合开始补至 **3 张**。
3. 每回合通常只能打出 **1 张**技能卡（无限火力为 3 张）。选择目标，打出，抛币。
4. 硬币 **50% 昭面 / 50% 昧面**：昭面结算卡牌正面效果，昧面结算反面效果。反面不一定是空过，常常是自伤、给对手回血或弃牌。
5. 每名玩家每局有 **1 次逆写**（重抛）。逆写后的结果必须接受。
6. 角色拥有 **被动** 与 **限定次数主动技**；主动技不消耗手牌，但每回合限一次。
7. 将对方队伍最后一名角色打到 **0 点生命** 即获胜。

更完整的结算顺序、模式规则与数值设计见 [docs/GAME_DESIGN.md](docs/GAME_DESIGN.md)。

## 五个娱乐模式

| 模式 | 一句话规则 |
| --- | --- |
| **镜像审判** | 双方同角色、同牌序；没有克制，只有你如何面对自己。 |
| **无限火力** | 每回合最多 3 张牌；每次抛币后仍留在自己的回合。 |
| **一币定生死** | 双方 1 点生命；治疗转化为护盾，一次成功伤害即终局。 |
| **连锁赌注** | 成功抛币叠 1 层连锁（最多 3），攻击加伤；失败清空并受等量反噬。 |
| **混沌换手** | 每个新回合所有人弃光手牌重抽 3 张；牌序不再属于你。 |

## 联机

### 公网联机（零配置，主推）

1. 房主打开「联机大厅」→ 默认就是「公网联机（零配置）」，创建房间，设置昵称、密码、模式与双方人数。
2. 把 `CF-XXXX` 房间号与密码发给对方。
3. 对方在「联机大厅」→ 加入房间填入即可。
4. 房主点「开桌」。访客的操作会作为“意图”发给房主，由房主引擎校验后广播权威状态。

> **无需任何配置，公网直连，WebRTC 点对点。** PeerJS 公共信令只用于握手，之后的对局数据走 WebRTC 点对点通道。房主与访客分处不同网络也能直连；房间号 + 密码就是暗号。

### 高级自定义（自建 PeerServer / Supabase，可选）

若所在网络屏蔽公共 PeerServer，可在「设置 → 联机」自建 PeerServer；Supabase Realtime 已降级为该页折叠的「高级自定义」项，仅在你想用自己的项目替代信令时填写。当前一个房间支持 **1 名真人访客**；队伍中的其余席位由 AI 同注者填充。

## AI 同注者

- 本地规则 AI 永远可用：简单随机、普通看血线、困难算收益并诱导你的逆写。
- 在「设置 → AI 接口」可接入任意 OpenAI 兼容接口。内置默认值：
  - Base URL：`https://maas.qianwenaiapi.com/compatible-mode/v1`
  - Model：`deepseek-v4.1-flash-1017`
  - API Key：已内置默认值（仅保存在浏览器 `localStorage`，可清空回退本地 AI）。
- 在战术频道用自然语言指挥，例如“先集火对面输出”“给我治疗”“别动，留着逆写”。AI 会结合角色性格、信任度、心情与当前血量判断是否服从；不合理时会顶嘴、讨价还价或拒绝。
- 详细配置、提示词与代理部署见 [docs/AI_GUIDE.md](docs/AI_GUIDE.md)。

> ⚠️ 浏览器会直连模型服务，Key 会出现在本机网络请求中。只在自己的设备上使用；公开部署请按 AI_GUIDE 搭一个服务端代理。

## 美术与音频

- **资源已升级为「真实素材 + 合成兜底」双层**：32 名角色立绘、主界面/对战背景、菜单配乐与出牌音效已就位；缺失的卡面/配乐/语音文件会自动回退到原有 CSS 程序化美术与 Web Audio 合成。
- 角色台词（出场/攻击/胜利/败北）已按人设在 `assets/voice-lines.js` 编写，共 32×4 句；无录音时由浏览器 TTS 自动朗读，放入对应 `.wav` 即自动切换真人录音。
- **目录、命名规范、触发时机、开源素材来源与许可证，见 [docs/ASSETS.md](docs/ASSETS.md)。**
- 每名角色、每张卡牌、每个 Boss 都带一段可直接用于图像生成的中文提示词，在游戏内图鉴点开即可复制。
- 导出全部提示词：

```bash
node tools/export-art-prompts.mjs
# 生成 ART_PROMPTS.md
```

- 8 个世界各有独立配乐参数（音阶、速度、波形），由 Web Audio 实时合成；硬币、伤害、治疗、技能均有音效；角色语音使用浏览器 SpeechSynthesis。
- 视觉规范、负面提示词、批量生成与替换建议见 [docs/ART_GUIDE.md](docs/ART_GUIDE.md)。

## 已知边界

- 房间密码只做“进门暗号”，是哈希后的门槛校验，**不是密码学级安全**；公网竞技请加服务端鉴权。
- Supabase anon key 是公开客户端凭据，安全性依赖 RLS；当前房间表仅用于展示，实际对局走 Broadcast。
- 一个房间只支持 1 名真人访客，其余队友/敌人为 AI。
- AI Key 存在浏览器本地；生产环境应改用服务端代理。
- 程序化美术是刻意设计的占位系统，替换为生成图需要额外接入图片字段与缓存。
