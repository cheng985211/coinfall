# 美术生成与替换指南

## 1. 当前美术系统

游戏没有外部图片依赖。所有“美术”由以下方式生成：

- **角色**：主题色渐变、字形徽记、粒子、卡框、CSS 纹理。
- **卡牌**：分类色、稀有度描边、风格符号、正/负面文案布局。
- **场景**：八个世界各自的 CSS 背景、光晕、噪点与动态粒子。
- **硬币**：CSS 3D 双面硬币，昭/昧两面有独立纹样。
- **Boss / 剧情**：程序化徽记与氛围层。

这套占位系统是有意设计，不是临时缺口：它保证零资源、零加载、零版权风险，并且在手机上也足够清晰。

每名角色、每张卡牌、每个 Boss 在 `data.js` 中都带有 `artPrompt` 字段，游戏内图鉴可以直接复制。

## 2. 视觉方向

### 2.1 总原则

- **暗色赌场 + 旧金描边**：背景接近黑，强调色克制，金色只用于“命运/货币/重要交互”。
- **每个世界一个主色**：八域并置时仍能一眼分辨。
- **卡框安全区**：主体不要贴边，给卡牌 UI 留出顶部名称、底部效果文案的空间。
- **无文字、无水印、无可辨认现有 IP**。
- **电影级布光 + 强轮廓**：缩到 124px 宽的手机手牌仍能读出角色/动作。

## 4. 提示词公式

`data.js` 已按以下结构生成提示词：

```text
[总风格] + [主体] + [世界观] + [视觉风格] + [气质/稀有度] + [构图要求] + [负面约束]
```

示例（角色）：

```text
暗黑奇幻集换式卡牌插画，电影级布光，精致细节，构图留出卡框安全区，无文字，无水印，横版 4:3。角色：执灯人·伊莱，深渊执灯人。世界观：沉钟海。风格：深海墨绿与病态青金，巨大不可名状的轮廓，烛火、湿石、古老仪式感，暗黑塔罗构图。气质：阴郁、克制，讨厌别人用命令的语气叫他“快点”。全身或半身英雄构图，轮廓清晰，背景可延展。
```

示例（卡牌）：

```text
暗黑奇幻集换式卡牌插画，电影级布光，精致细节，构图留出卡框安全区，无文字，无水印，横版 4:3。卡牌：「试探性刺击」。类型：攻击。世界观：沉钟海（克苏鲁）。视觉：深海墨绿与病态青金，巨大不可名状的轮廓，烛火、湿石、古老仪式感，暗黑塔罗构图；攻击性动作、锋利的动势、火星与残影。稀有度气质：普通。卡面允许出现象征性法器或角色剪影，但不要出现可辨认的现有 IP 角色。
```

### 推荐负面提示词

```text
text, watermark, logo, signature, UI, card frame, border, lowres, blurry, bad anatomy,
extra fingers, deformed hands, duplicate character, collage, split screen, oversaturated,
neon rainbow, modern logo, copyrighted character, existing anime IP, photorealistic face
```

### 生成参数建议

- 比例：4:3（角色/卡牌），16:9（背景），1:1（硬币/Boss 头像）。
- 步数：28–40；CFG：5–7；采样器按模型推荐。
- 每个角色固定一个 seed，方便生成“同一角色的不同动作”。
- 先为每个世界生成 1 张“风格锚图”，再以图生图 / 参考图保持统一。
- 卡牌不要生成文字；名称、效果、稀有度由 HTML/CSS 叠加。

## 5. 批量生成建议

### 5.1 导出全部提示词

```bash
node tools/export-art-prompts.mjs
```

生成 `ART_PROMPTS.md`，包含：

- 8 个世界的美术方向。
- 32 名角色的完整提示词。
- 150 张卡牌的完整提示词。
- 3 个 Boss 的提示词。
- 负面提示词与命名规范。

### 5.2 文件命名

```text
assets/art/characters/cth-01.webp
assets/art/cards/attack-001.webp
assets/art/realms/abyss.webp
assets/art/modes/frenzy.webp
assets/art/bosses/boss-01.webp
assets/art/coin/sun.webp
assets/art/coin/moon.webp
```

统一 WebP，质量 80–86；卡牌可再生成 512px 缩略图用于列表。

### 5.3 一致性检查

- 同一世界的角色是否共享光源方向与色温。
- 角色轮廓在 124px 宽时是否仍可辨认。
- 卡牌主体是否避开顶部 18% 与底部 28% 的文案区。
- 是否有文字、边框、UI 被生成进图里。
- 是否存在与现有 IP 过于相似的角色。

## 6. 替换进游戏

当前版本不自动加载图片。若要接入生成图，建议按以下顺序：

1. 在 `data.js` 为角色/卡牌增加 `artUrl`（或 `art`）字段。
2. 在 `game.js` 的卡牌/角色渲染处，如果存在 `artUrl`，输出 `<img loading="lazy" src="...">`，否则保留现有 CSS 占位。
3. 在 `style.css` 给图片容器加 `object-fit: cover`、固定比例与暗部遮罩，保证文字可读。
4. 为加载失败保留占位：`onerror` 时移除 `img`，回退到当前渐变卡面。
5. 背景图放在 `realms/<style>.webp`，用 CSS 变量或内联 `background-image` 切换。

伪代码：

```js
const art = card.artUrl
  ? '<img class="card-art" loading="lazy" src="' + card.artUrl + '" alt="">'
  : '<span class="card-art card-art--placeholder">' + glyph + '</span>';
```

> 注意：GitHub Pages 对单文件 100MB、仓库 1GB 有软限制。150 张 1024px WebP 通常在 30–80MB，建议用 CDN 或按需加载。

## 7. 版权与合规

- 不要直接生成/使用现有动漫、游戏、电影角色。
- “经典动漫/小说”世界的角色是原创致敬，提示词中已注明“不要出现可辨认的现有 IP 角色”。
- 不使用真实人物肖像。
- 保留生成记录与模型许可，商用前确认服务条款。
- 若使用第三方图库/生成图，在 README 或关于页注明来源与许可。
