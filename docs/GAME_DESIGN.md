# 命途回廊 · COINFALL — 游戏设计文档

版本 1.0 · 纯前端浏览器游戏 · 2–8 名角色（1v1 至 4v4）

---

## 1. 设计概览

### 1.1 一句话

一款“每次行动都要抛币”的回合制卡牌对战游戏：你必须在硬币落下之前，决定要不要把命运押上去。

### 1.2 设计支柱

1. **一次行动，一次心跳。** 出牌不是执行指令，而是把结果交给硬币；正面与反面都必须有戏剧性。
2. **短局、高密度。** 5 点生命、3 张手牌、每回合 1 张牌，单局通常 5–12 分钟。
3. **人格化的队友。** 队友不是技能按钮，而是会判断、会抱怨、会记仇的“同注者”。
4. **八个世界，一套规则。** 风格差异通过角色、卡牌文案、主题色与配乐表达，不增加规则负担。
5. **打开就能玩。** 零构建、零后端、桌面与手机同一套界面。

### 1.3 目标体验

- 新手第一局：30 秒理解“选牌 → 抛币 → 昭/昧结算”。
- 老手第十局：开始计算逆写时机、连锁层数、对手手牌上限与角色被动。
- 联机局：像围坐一桌，能指挥队友、能互相嘴炮、能因为一次重抛翻盘。

## 2. 世界观

### 2.1 核心设定

在时间之外，有一座不存在的赌场——**命途回廊**。它由“无主铸币局”在第一次选择发生时建成。回廊中央悬着一枚双面硬币：

- **昭面**：事件成立，技能按正面效果结算。
- **昧面**：事件反噬，技能按负面效果结算。
- **第三面**：硬币立起来。传说中只有同注者默契足够高时才会出现。

八个世界正在失去自己的结局。庄家准备把所有残余故事熔成唯一一个“完美终章”。被硬币选中的人被称为**执币者**，他们带着角色卡与技能卡入席，用五点生命和一局胜负，替某个世界争取继续讲述的权利。

### 2.2 八个世界

| 世界 | 领域 | 核心矛盾 | 视觉关键词 |
| --- | --- | --- | --- |
| 克苏鲁 | 沉钟海 | 第十三声钟响后，海会忘记自己曾是海 | 深海墨绿、病态青金、巨物轮廓、烛火湿石 |
| 蒸汽朋克 | 黄铜穹顶 | 始动之心只剩三转，有人在故意让它停摆 | 黄铜齿轮、护目镜、蒸汽火花、煤黑暖金 |

| 西式奇幻 | 圣誓原野 | 龙在苏醒，王国却为“谁拥有末日”内战 | 哥特圣殿、鎏金盔甲、星图龙翼、彩窗 |

### 2.3 阵营

- **守夜人**：试图保留八个世界各自的结局，认为故事的价值在于未完成。
- **裂隙赌团**：贩卖房间号与“必赢局”，靠制造确定性牟利。
- **无主铸币局**：庄家的产业，负责把命运标准化、定价、回收。
- **同注者**：与执币者共享赌注的 AI 或玩家。他们不是仆从，有自己的判断与脾气。

### 2.4 三种结局

1. **昭面结局**：你替某个世界赢回继续讲述的权利，但回廊仍在。
2. **昧面结局**：你成为庄家的一部分，开始为下一桌发牌。
3. **第三面**：在 2v2 中与同注者默契 ≥10，硬币立起，所有世界保留不完美的结局。

## 3. 核心规则

### 3.1 对局结构

- **双方**：A 队与 B 队。每队 1–4 名执币者（自由组队模式）。
- **每名执币者**：1 名角色（大乱斗为 2 名）、5 点生命、一副技能卡、1 次逆写。
- **座位**：A1 → B1 → A2 → B2 … 交替行动；只有存活玩家进入行动序列。
- **回合**：一名玩家从“行动阶段”开始，出牌 → 抛币 → 结算 → 揭示 → 下一位。
- **轮次**：行动序列回到第一位存活玩家时，轮次 +1。

### 3.2 开局

1. 双方各选 1 名角色（大乱斗 2 名），洗牌。
2. 各抽 3 张起手牌。
3. 随机决定先手；先手第一回合不补牌。
4. 角色被动在开局或对应时机自动生效（护盾、先手等）。

### 3.3 回合流程

```text
回合开始
  ├─ 清理本回合标记
  ├─ 混沌换手（若模式启用且新轮次）
  ├─ 补牌至 3（受“锁喉”影响可少于 3）
  ├─ 回春等回合开始被动
  ▼
行动阶段
  ├─ 打出 1 张技能卡（无限火力 3 张）→ 选择目标 → 抛币
  │    ├─ 昭面：正面效果
  │    └─ 昧面：反面效果
  ├─ 可使用 1 次角色主动技（不消耗手牌）
  ├─ 可免费切换角色（大乱斗，每回合 1 次）
  └─ 结束回合
  ▼
揭示阶段（短暂展示结果）
  ▼
下一位存活玩家
```

### 3.4 抛币与逆写

- 每次出牌独立抛币，`Math.random() < 0.5` 为昭面。
- **逆写**：每名玩家每局 1 次，可在硬币落定前重抛；重抛后必须接受。
- 某些卡牌/主动技给予“命运祝福”，使下一次抛币必定昭面；此时不能逆写。
- 逆写不是“取消”：它只是再给命运一次机会，反面效果依然可能落下。

### 3.5 伤害、护盾与治疗

- 伤害先扣护盾，再扣生命；`pierce` 无视护盾。
- 治疗不能超过生命上限；一币定生死模式中，治疗全部转化为护盾。
- 反伤、直接伤害（如连锁断裂）可绕过普通伤害修正，但仍受“直接伤害”规则约束。
- 生命归零的角色退场；队伍最后一名角色退场时，对方获胜。

### 3.6 胜负

- 对方队伍全部角色生命为 0 → 获胜。
- 牌库与弃牌堆都耗尽时，仍可结束回合；不会因无牌直接判负。
- 主动投降/离开联机房间按弃权处理。

### 4.3 性格与语音

每个角色有独立的 `temper`（脾气）、`quote`（口头禅）与 `bio`（小传）。AI 同注者会把这些字段注入回复生成：阴郁的执灯人不会热情地说“好的老板”，赌徒会拿逆写开玩笑，防御角色会优先要求你保命。

## 5. 卡牌系统

### 5.1 分类

| 分类 | 数量 | 设计职责 | 代表效果 |
| --- | ---: | --- | --- |
| 攻击 | 30 | 直接伤害、破盾、弃牌 | `dmg`、`pierce`、`strip`、`discard` |
| 防御治疗 | 30 | 护盾、回复、反制 | `shield`、`heal`、`oppHeal` |
| 功能控制 | 30 | 抽牌、锁喉、封印 | `draw`、`choke`、`seal`、`oppDraw` |
| 高风险收益 | 30 | 高数值 + 明确反噬 | 高伤/自伤、赌博式抽牌 |
| 风格专属 | 30 | 八个世界的标志性招式 | 混合效果、主题化文案 |

### 5.2 稀有度

| 稀有度 | 权重 | 设计意图 |
| --- | ---: | --- |
| 普通 | 1 | 稳定、低上限 |
| 稀有 | 2 | 有明确构筑价值 |
| 史诗 | 3 | 改变回合节奏 |
| 传说 | 4 | 高风险高回报，有构筑核心潜力 |

### 5.3 效果词汇

`dmg` 伤害 · `selfDmg` 自伤 · `pierce` 无视护盾 · `strip` 击碎护盾 · `heal` 治疗 · `shield` 护盾 · `draw` 抽牌 · `discard` 令对手弃牌 · `oppDraw` 令对手抽牌（负面） · `oppHeal` 令对手回复（负面） · `choke` 下回合少抽 · `seal` 封印主动技 · `bless` 下一次抛币必昭。

### 5.4 构筑

- 标准模式牌库 15 张；自定义卡组从 150 张中选 **正好 10 张**。
- 起手 3 张，每回合补至 3 张；弃牌堆耗尽后洗回牌库。
- 自定义卡组会持久化到 `localStorage`，下次打开仍在。
- 设计上鼓励“正面收益 / 反面代价”不对称：没有零代价的强牌。

## 6. 模式设计

### 6.1 核心模式

| 模式 | 规则要点 | 目标体验 |
| --- | --- | --- |
| 标准对战 | 1v1，5 HP，每回合 1 张牌 | 规则基准 |
| 大乱斗 | 每人 2 名角色，每回合免费切换 1 次，全灭才负 | 角色组合与切换时机 |
| 无尽赌徒 | 无逆写，所有卡牌/主动技数值翻倍 | 短、疯、接近庄家口味 |
| 人机对战 | 三档 AI | 学习与练习 |
| 随机卡组 | 双方从 150 张随机成牌 | 快速体验不同流派 |
| 指定卡组 | 自选 10 张 | 构筑与针对性 |
| 自由组队 | 双方 1–4 人，可不对等；AI 同注者 | 指挥、配合、嘴炮 |
| 快速模式 | 生命上限 3 | 10 分钟内一局 |
| 剧情挑战 | 3 章 Boss，更高生命/特殊被动 | 世界观与 PvE |
| 局域网联机 | PeerJS P2P，房间号 + 密码 | 同屋开黑 |
| 公网联机 | Supabase Realtime | 远程对战 |

### 6.2 五个娱乐模式

#### 镜像审判（mirror）

双方使用同一名角色、同一套牌序。角色克制与卡组差距被抹平，胜负只取决于抛币、逆写与出牌顺序。适合决斗与复盘。

#### 无限火力（frenzy）

每回合最多 3 张牌，牌库扩至 18 张。每次结算后不切换行动者，直到打完 3 张或主动结束回合。连锁反应让单回合可以打出爆发，也更容易连续吃反面。

#### 一币定生死（sudden）

双方生命上限 1。任何成功伤害立即终局；治疗转化为护盾。一次判定就是全部，逆写价值极高。

#### 连锁赌注（chain）

昭面累积 1 层连锁（最多 3），攻击伤害 +层数；昧面清空连锁并受到等量直接反噬。奖励连续成功，也惩罚贪心。

#### 混沌换手（chaos）

每个新回合所有人弃光手牌重抽 3 张。牌序不再属于你，适应混乱、保留关键牌的人才能活到最后。

### 6.3 自由组队

- 双方人数各自在 1–4 之间独立选择，允许 1v4、2v3 等不对等局。
- 座位按 A1、B1、A2、B2… 交替；人数多的一方多出的席位排在最后。
- 真人只控制自己的角色；同队其余席位由 AI 同注者填充。
- 队友指令通过战术频道自然语言下达；AI 会判断合理性、信任度与心情后决定服从或反驳。
- 队友可切换焦点，查看其手牌/血量/主动技；联机时只隐藏敌方手牌。

## 7. 平衡与数值

### 7.1 基线

- 5 HP、每回合 1 张牌、50% 昭面。
- 单张牌期望伤害约 1.0–1.5；治疗期望 1.5–2；护盾 1–2。
- 一局约 8–16 个玩家回合；标准局平均 7–10 分钟。

### 7.2 模拟结果

引擎回归脚本以固定种子跑 232 局（12 个模式 × 18 局 + 16 组组队人数矩阵），另做 10 次镜像一致性校验，共 7,561 回合，A/B 胜率 100/116，无卡死局。结果用于发现异常状态与死循环，不作为严格胜率平衡依据。

### 7.3 风险点

- 无限火力中连续昭面可能形成单回合斩杀；通过 3 张上限与反面自伤约束。
- 一币定生死先手优势明显；逆写与护盾是主要缓冲。
- 连锁赌注存在“滚雪球”；失败反噬与 3 层上限用于回摆。
- 自由组队人数不对等时，多打少方有行动次数优势；AI 强度与手牌资源需要继续观察。

## 8. 联机架构

### 8.1 房主权威

```text
访客 UI ──意图(action/flip/chat)──▶ 房主引擎
   ▲                                  │
   └──── 脱敏后的权威状态(state) ◀────┘
```

- 访客不能直接修改游戏状态，只能提交“打出第 N 张牌 / 接受 / 逆写 / 结束回合”等意图。
- 房主校验回合、手牌、目标、次数后结算，再向访客广播 `serializeFor(viewerId)` 的结果。
- 敌方手牌在序列化时被替换为牌背；己方队友手牌可见；指令与聊天单独同步。
- 断线、离开、房间关闭通过 `bye` / `leave` 事件回到大厅。

### 8.2 传输

- **PeerJS**：公共信令完成 SDP/ICE 交换，之后 WebRTC DataChannel 点对点。房间号映射为固定 peer id；密码做哈希门槛校验。
- **Supabase Realtime**：Broadcast 传输消息，Presence 判断房主/访客在线；可选 `coinfall_rooms` 表用于房间目录。
- 两种传输共用同一套消息协议与房主权威逻辑。

### 8.3 安全边界

- 房间密码是“进门暗号”，不是加密；知道房间号的人仍可能尝试暴力猜密码。
- Supabase anon key 是公开客户端凭据，必须配合 RLS；当前设计不存储敏感数据。
- 生产级排位/赛事应增加服务端鉴权、回放校验与速率限制。

## 9. AI 设计

### 9.1 三档本地 AI

- **简单**：随机选牌，几乎不用主动技，逆写决策接近随机。
- **普通**：看血线、护盾与手牌，优先打出高期望牌；22% 概率放弃主动技。
- **困难**：计算收益、保留关键牌、诱导对手逆写；在合适时机使用主动技与重抛；可接入 LLM 做战斗决策。

### 9.2 同注者人格

每个 AI 队友维护：

- `trust`（0–12）：对指挥者的信任。
- `mood`（0–100）：当前心情。
- 角色 `temper` / `bio` / `quote`：说话方式。
- `orders`：已接受的指令，带回合与目标。

指令解析覆盖：集火、攻击、防御、治疗、开主动、过牌、保留、撤退、称赞、辱骂、问候、询问状态。AI 会判断：

- 目标是否合法、是否值得打。
- 当前血量是否需要治疗/护盾。
- 指令是否与自己的性格冲突（例如让赌徒“别赌”）。
- 信任与心情是否足够服从；不合理时给出有性格的反驳。

### 9.3 LLM 增强

- 任意 OpenAI 兼容接口；默认 `https://maas.qianwenaiapi.com/compatible-mode/v1` + `deepseek1017`。
- 用于：战斗决策（困难）、自然语言回复、主动嘴炮、战后总结。
- 失败自动回退本地启发式，不阻塞对局。
- Key 仅存 `localStorage`；公开部署应使用服务端代理。

详见 [AI_GUIDE.md](AI_GUIDE.md)。

## 10. 表现与交互

### 10.1 视觉

- 深色赌场基底 + 旧金描边 + 每个世界独立主题色。
- 角色/卡牌用 CSS 渐变、纹理、字形与光效生成“占位美术”，不依赖图片。
- 硬币 3D 翻转、昭/昧粒子爆发、伤害数字、治疗光晕、护盾破裂、连锁闪电等六类事件动画。
- 响应式：桌面横屏三栏战场；手机竖屏压缩手牌与战场，保持可点击尺寸。

### 10.2 音频

- 8 个世界独立 BGM 参数（根音、音阶、速度、波形），Web Audio 实时合成。
- 硬币、出牌、伤害、治疗、护盾、按钮、聊天等音效。
- 角色语音为真人 wav 录音；文件缺失时静默（v2.1 起无浏览器语音合成）。

### 10.3 可访问性

- 主要按钮有 `aria-label`，战斗日志与聊天为 `aria-live`。
- 支持减少动态效果（跟随系统 `prefers-reduced-motion`）。
- 键盘：Enter 发送聊天，Esc 关闭弹窗。
- 颜色对比以深色底 + 亮金/浅色文字为主；主题切换不改变信息层级。

## 11. 技术架构

```text
index.html
  ├─ data.js   （UMD，浏览器 + Node 共用）
  ├─ ai.js     （CF_AI）
  ├─ net.js    （CF_NET）
  └─ game.js   （CF_ENGINE 规则引擎 + CF_UI 控制器）
```

- **无构建**：脚本按顺序加载，全局命名空间。
- **引擎/UI 分离**：`CF_ENGINE` 可在 Node 中直接跑模拟；`game.js` 在 Node 环境导出引擎后提前返回，不触碰 DOM。
- **确定性**：引擎接受注入的 `rng`，测试可用固定种子复现。
- **状态序列化**：`serializeFor(game, viewerId)` 生成脱敏视图，联机与本地渲染共用。
- **存档**：设置、卡组、主题、AI 配置存 `localStorage`；无账号系统。
